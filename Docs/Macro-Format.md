# 매크로 JSON 형식

코드를 쓰지 않고 매크로를 정의하는 형식이다.
`Scripts\Common\macro_engine.py`가 이 JSON을 읽어 OculiX API로 실행한다.

**이 형식을 직접 편집할 필요는 없다.** GUI 편집기가 있다.

```powershell
python D:\Programming\Oculix-Automation\Tools\MacroEditor\macro_editor.py
```

편집기 사용법은 아래 "GUI 편집기" 절 참조. 이 문서의 나머지는 형식 자체의
레퍼런스이고, 편집기가 무엇을 만들어내는지 이해하거나 손으로 고칠 때 본다.

---

## 두 가지 형식

| 형식 | 키 | 편집 화면 | 비고 |
|---|---|---|---|
| **그래프** | `nodes` + `links` | 노드 캔버스 | 새로 만들면 이쪽. 자유 연결 |
| 트리 | `steps` | 단계 트리 | 예전 형식. 그대로 실행된다 |

`Scripts\Runner\RunMacro.sikuli`가 형식을 보고 알아서 실행기를 고른다.
트리 형식은 `도구 > 그래프로 변환`으로 노드 화면에서 편집할 수 있다.

---

## 노드 그래프 (UE 블루프린트 방식)

노드를 선으로 이어 실행 순서를 만든다. 트리와 달리 **연결이 자유롭다** —
두 갈래가 한 노드로 합류할 수도 있고, 앞의 노드로 되돌아갈 수도 있다.

```json
{
  "name": "보상 수령",
  "version": 2,
  "format": "graph",
  "settings": { "maxSteps": 5000, "maxSeconds": 300 },
  "entry": "n1",
  "nodes": [
    { "id": "n1", "type": "click", "image": "menu.png", "ui": { "x": 60, "y": 60 } },
    { "id": "n2", "type": "if", "condition": { "type": "imageExists", "image": "popup.png" },
      "ui": { "x": 310, "y": 60 } }
  ],
  "links": [
    { "from": "n1", "pin": "next",  "to": "n2" },
    { "from": "n2", "pin": "true",  "to": "n3" },
    { "from": "n2", "pin": "false", "to": "n4" }
  ]
}
```

**실행 출력 핀**

| 노드 | 핀 |
|---|---|
| 대부분 | `next` + `fail` |
| 조건 분기 | `true` / `false` + `fail` |
| 반복 | `body` / `completed` + `fail` |
| 반복 빠져나오기 | 없음 |

출력 핀 하나에는 연결이 **하나만** 붙는다(블루프린트와 동일).
입력에는 여러 연결이 모일 수 있다.

### 실패 핀 — 실패했을 때 다른 경로로

`break` 를 뺀 모든 노드에 **붉은 `실패` 핀**이 하나 더 있다.
여기에 노드를 연결하면 그 단계가 실패했을 때 그쪽으로 흐른다.

```text
[버튼 찾기] --다음--> [클릭] --다음--> [계속]
     |
     +--실패--> [새로고침] --다음--> [다시 찾기]
```

실패했을 때 어디로 가는지는 이 순서로 정해진다.

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | `실패` 핀에 연결된 노드가 있음 | 그쪽으로 진행. 매크로는 계속 돌아간다 |
| 2 | 연결 없고 `실패 시: 무시하고 계속` | 평소 진행 핀으로 |
| 3 | 그 외 | 매크로 중단 |

**실패 핀이 `실패 시` 설정보다 우선한다.**
둘 다 지정하면 검사가 설정 쪽은 쓰이지 않는다고 알려준다.

흐름 노드에도 적용된다.

* **반복** — 본문이 실패하면 반복을 멈추고 반복 노드의 `실패` 핀으로
* **매크로 호출** — 호출한 매크로가 실패하거나 찾지 못하면 `실패` 핀으로
* **조건 분기** — 조건을 평가하다 오류가 나면 `실패` 핀으로

쓰임새가 없는 노드(`로그` 등)에도 핀은 있지만 그저 쓰이지 않는다 —
노드마다 규칙이 달라지지 않게 단순하게 둔 것이다.

**반복 노드의 동작** (`times` / `while` / `forEach` 셋 중 하나)

`body`로 이어진 체인을 실행하고, 그 체인이 **연결이 끊긴 지점에서 끝나면**
반복 노드로 돌아온다. 정해진 횟수나 조건이 끝나면 `completed`로 나간다.
블루프린트의 ForLoop과 같은 방식이다.

**꺼진 노드**

`enabled: false`인 노드는 건너뛴다. 어느 핀으로 나갈지는 정해져 있다.

```text
조건 분기를 끄면  ->  false 로 (조건이 거짓인 것으로 취급)
반복을 끄면       ->  completed 로 (본문을 건너뜀)
그 외             ->  next 로
```

**순환과 실행 예산**

자유 연결이므로 앞 노드로 되돌아가는 순환을 만들 수 있고, 그건 무한 루프다.
`반복` 노드 없이 순환을 만들면 검사가 경고하지만 막지는 않는다.
대신 **실행 예산**이 반드시 걸린다.

```json
"settings": { "maxSteps": 5000, "maxSeconds": 300 }
```

`maxSteps`는 노드 실행 횟수 총합, `maxSeconds`는 벽시계 시간이다.
둘 중 하나라도 넘으면 실행이 중단되고 어느 노드에서 걸렸는지 로그에 남는다.
이 예산은 끌 수 없다. 자유 그래프에서 무한 루프를 막는 유일한 장치이기 때문이다.

**노드 캔버스 조작**

```text
노드 몸통 드래그       위치 이동
출력 핀에서 드래그     다른 노드에 놓으면 연결 / 빈 곳에 놓으면 연결 해제
연결선 클릭 후 Delete  연결 삭제
Ctrl + C / Ctrl + V    고른 노드 복사 / 붙여넣기 (아래 참조)
Ctrl + D               고른 노드 복제 (아래 참조)
빈 곳 우클릭           노드 추가, 붙여넣기, 보기 초기화, 자동 정렬
노드 우클릭            시작 노드 지정 / 사용 해제 / 복제 / 복사 / 붙여넣기 / 삭제
호출 노드 더블클릭     호출 대상 매크로를 연다
가운데 버튼 드래그     화면 이동
휠                     확대 / 축소
```

**노드 복사 / 붙여넣기**

여러 개를 골라 `Ctrl+C` 로 복사하고 `Ctrl+V` 로 붙여넣는다. 같은 매크로 안은
물론 **다른 매크로에도** 붙는다. 클립보드에 JSON 글자로 담기므로 편집기를
두 개 띄워 놓아도 오간다. 붙는 자리는 마우스 커서가 가리키는 곳이다.

키는 캔버스 위젯에만 걸려 있다. 속성 패널의 입력칸에서는 평소대로 글자가
복사된다.

**노드 복제 (`Ctrl+D`)**

고른 노드를 그 자리 옆에 복제한다. 하나만 골랐으면 그 노드만 만든다.
**여러 개를 골랐으면** 노드 사이의 연결까지 함께 복제한다 - 내부적으로
`Ctrl+C` → `Ctrl+V` 와 같은 길을 지나므로 **클립보드 내용이 덮어쓰인다.**

옮기면서 세 가지를 손본다. 규칙은 `Tools\MacroEditor\nodeclip.py` 에 있다.

* **노드 id** — 새로 발급하고 꾸러미 안의 연결을 새 id 로 고쳐 잇는다.
  고른 노드 **사이**의 연결만 따라온다. 선택 밖으로 나가던 연결은 빠진다.
* **이미지** — 원본 매크로 폴더에서 파일을 복사해 온다.
  같은 이름이 이미 있으면 **덮어쓰지 않는다.** 내용이 같으면 그대로 쓰고,
  다르면 `이름 (2).png` 로 가져온 뒤 붙여넣은 노드의 참조만 그 이름으로 바꾼다.
  (남의 매크로가 쓰고 있는 그림을 조용히 갈아치우는 사고를 막는다.)
* **호출 참조** — `./이름` 하위 매크로 참조는 그 가족 안에서만 뜻이 있다.
  다른 가족에 붙이면 가리킬 곳이 없어진다. 참조를 몰래 고치지 않고
  붙여넣은 직후 로그에 `주의: 노드 ...: 호출 대상을 찾을 수 없습니다` 로 알린다.
  대상을 다시 지정해야 한다.

시작 노드는 바뀌지 않는다. 다만 **빈 매크로**에 붙여넣으면 붙은 첫 노드가
시작 노드가 된다.

시작 노드는 초록 테두리와 `시작` 표시로 구분된다.
노드 색은 종류 그룹을 따른다 — 화면(파랑) / 마우스(초록) / 키보드(주황) / 흐름(보라).

**노드에 표시되는 것**

```text
┌─────────────────────────────┐
│ 이미지 나타날 때까지 대기    │  ← 이름 (없으면 종류)
├─────────────────────────────┤
│ ▶Exec              다음 Exec▶│  ← 핀 이름 + 타입
│                              │
│      [이미지 미리보기]       │  ← image 매개변수가 있으면
│  target.png                  │  ← 요약
└─────────────────────────────┘
```

핀 타입은 지금 실행 핀(`Exec`) 하나뿐이다. 값을 넘기는 데이터 핀이 생기면
여기에 타입이 늘어난다. 정의는 `Scripts\Common\graph_model.py`의
`PIN_TYPE_*` 에 있고 편집기가 그 값을 읽어 표시한다.

이미지 매개변수가 있는 노드는 그 이미지의 **썸네일을 노드 안에 그린다.**
캔버스를 확대/축소하면 썸네일도 함께 커지고 작아진다.

`PhotoImage` 는 정수 배율만 지원하지만(`zoom(n)` 확대, `subsample(n)` 축소),
둘을 조합한 `zoom(a).subsample(b)` = `a/b` 배로 임의 배율을 근사한다.
정수 근사라 요청 크기와 몇 픽셀 다를 수 있어 자리 안에서 가운데 정렬한다.

**노드 높이는 확대율과 무관하다.** 썸네일이 차지하는 자리는 원본 비율로 계산한
월드 좌표 크기로 잡고, 그리기만 확대율을 곱한다. 이렇게 하지 않으면 확대할
때마다 노드가 늘었다 줄었다 한다.

**실행 가능한 예제**

`Macros\ExampleGraph\macro.json` — 트리 예제를 그래프로 변환한 것.
편집기에서 열어 F5로 바로 실행할 수 있다.

## 매크로 호출 — 함수처럼 재사용하기

블루프린트의 Function처럼, 만들어 둔 매크로를 다른 매크로에서 노드 하나로 부를 수 있다.
로그인, 팝업 닫기처럼 반복되는 절차를 한 번만 만들면 된다.

```json
{ "type": "call", "label": "팝업 정리", "macro": "Common/ClosePopup" }
```

`macro` 값은 `Macros` 폴더 기준 경로다.

```text
"ClosePopup"            Macros/ClosePopup/macro.json
"Common/ClosePopup"     Macros/Common/ClosePopup/macro.json
```

**편집기에서**

왼쪽 위 `매크로 라이브러리` 패널에 Macros 폴더의 매크로가 모두 나온다.
지금 열려 있는 매크로에는 `●` 표시가 붙는다.

| 조작 | 결과 |
|---|---|
| **끌어다 놓기** | 캔버스에 놓은 자리에 호출 노드가 생긴다 |
| **더블클릭** | 그 매크로를 **편집하러 연다** |
| `호출 노드 추가` 버튼 | 고른 매크로의 호출 노드를 추가 |
| **우클릭** | 편집 / 호출 노드로 추가 / 이름 변경 / 복제 / 삭제 / 탐색기 |

**이름 변경**은 폴더 이름을 바꾸고, **그 매크로를 호출하는 다른 매크로의 참조도
함께 고친다.** 몇 군데를 고칠지 먼저 알려준다.

**삭제**는 폴더를 통째로 지운다. 호출하는 곳이 있으면 몇 군데인지 경고하고,
이 프로젝트가 버전 관리를 쓰지 않아 되돌릴 수 없다는 점도 함께 알린다.
지금 편집 중인 매크로는 삭제할 수 없다.

**동작 규칙**

| 항목 | 규칙 |
|---|---|
| 이미지 | 호출된 매크로는 **자기 폴더**의 이미지를 쓴다 |
| 설정 | 호출된 매크로의 `settings`를 쓴다 (자기 완결적) |
| 복귀 | 호출된 매크로의 흐름이 끝나면 호출 노드의 `next`로 돌아온다 |
| 실패 | 호출 대상이 실패하면 호출 노드도 실패. `onFail: continue`로 넘길 수 있다 |
| 예산 | `maxSteps` / `maxSeconds`는 **최상위 매크로 것 하나**를 전체가 공유한다 |
| 깊이 | 중첩 호출은 16단계까지 |
| 순환 | A→B→A는 작성 시점 검사와 실행 시점 양쪽에서 막는다 |

예산 공유가 중요하다. 호출된 매크로가 자기 예산을 새로 시작하면 상한이 무의미해지므로,
호출을 몇 번 건너가든 전체 실행에 예산은 하나뿐이다.

트리 형식 매크로도 호출 대상이 될 수 있다.

**매개변수를 가진 매크로를 단독으로 실행할 때**

편집기에서 `F5` 나 `Shift+F5` 로 직접 돌리면 값을 넘겨주는 호출 노드가 없다.
이때는 **선언에 적어 둔 기본값을 그대로 쓴다.** 어떤 값을 썼는지 로그 맨 앞에 남는다.

```text
단독 실행 - 매개변수 기본값을 씁니다: count=1, flag=True
단독 실행 - 기본값이 없어 비워 둔 매개변수: who
```

기본값이 없는 매개변수는 채울 방법이 없으므로 비워 둔 채 진행한다.
그 매개변수를 보는 조건은 값이 없는 상태로 비교하게 되니, 단독으로 시험할
매크로에는 기본값을 적어 두는 편이 낫다. 실행 자체를 막지 않는 이유는
그러면 매개변수를 가진 매크로를 혼자 열어 볼 수 없게 되기 때문이다.

**실행 로그**

호출된 매크로의 로그는 `|` 로 들여써서 구분된다.

```text
--> 팝업 정리 1  [호출: Common/ClosePopup]
    | === 팝업 닫기 (공용) (그래프) ===
    | --> 팝업 있나?
    |     조건 -> False
    | === 노드 2회 실행, 실패 0 -> OK ===
    호출 완료: Common/ClosePopup
--> 본 작업
```

**예제**

`Macros\CallDemo\` 가 `Macros\Common\ClosePopup\` 을 두 번 호출한다.
편집기에서 열어 F5로 실행해 볼 수 있다.

## 하위 매크로 — 부모 전용 함수

UE 블루프린트에 빗대면 이렇게 나뉜다.

| UE BP | 이 프로젝트 | 어디에 있나 |
|---|---|---|
| 다른 BP / 이벤트 | **매크로 라이브러리** | `Macros\<이름>\` |
| 그 BP의 **함수** | **하위 매크로** | `Macros\<부모>\<이름>\` |

매크로 폴더 **안에** 매크로 폴더를 만들면 그것이 하위 매크로다.
부모의 사유물이라 라이브러리 목록에 뜨지 않고, 그 가족만 호출할 수 있다.

```text
Macros\
└─ MBM_Daily\
   ├─ macro.json          부모
   ├─ menu.png            이미지 - 가족이 함께 쓴다
   ├─ reward.png
   ├─ OpenMenu\
   │  └─ macro.json       하위 매크로 (이미지는 위의 것을 이름만으로 참조)
   └─ ClosePopup\
      └─ macro.json
```

**참조 표기**

```json
{ "type": "call", "macro": "./OpenMenu" }
```

`./` 로 시작하면 **가족 안에서만** 찾는다. 라이브러리에 같은 이름의 매크로가
있어도 그쪽으로 새지 않는다. 반대로 `"MBM_Daily/OpenMenu"` 처럼 경로로 남의
하위를 집으면 검사와 실행 양쪽에서 거부된다.

**규칙**

| 항목 | 하위 매크로 | 라이브러리 매크로 |
|---|---|---|
| 이미지 | **부모 폴더**의 것을 이름만으로 | 자기 폴더 |
| `settings` | **부모 것을 상속** (자기 것은 무시) | 자기 것 |
| 호출할 수 있는 쪽 | 부모와 형제만 | 누구나 |
| 중첩 | 1단계까지 (하위의 하위는 없음) | 해당 없음 |
| 예산·순환·깊이 | 라이브러리 호출과 동일 | — |

설정을 상속하는 이유는 이미지를 공유하기 때문이다. 정확도나 모니터가 부모와
다르면 같은 이미지가 부모에서는 잡히고 하위에서는 안 잡히는 일이 생긴다.
그래서 하위 매크로의 `macro.json` 에는 `settings` 를 아예 두지 않는다
(편집기가 만들 때 빼 준다). 설정 대화상자를 열면 상속 중이라고 알려 준다.

하위 매크로를 편집기에서 열어 **F5 로 바로 실행**해도 같은 문맥이 적용된다.
호출로 돌 때와 단독으로 돌 때가 다르면 테스트만 통과하고 본 실행이 깨지므로,
실행기가 부모를 찾아 설정과 이미지 폴더를 물려준다. 로그 첫 줄에 이렇게 남는다.

```text
하위 매크로 - 부모(MBM_Daily)의 설정과 이미지 폴더를 사용합니다
```

**편집기에서**

왼쪽 `하위 매크로` 패널에 지금 연 매크로의 가족이 보인다. 라이브러리 패널과
조작법이 같다 — 더블클릭으로 열고, 캔버스로 끌어다 놓으면 호출 노드가 되고,
우클릭으로 이름 변경·복제·삭제할 수 있다. 하위를 편집하는 동안에는
`⬑ 부모 매크로 열기` 로 되돌아간다. 이름을 바꾸면 **가족 안의 호출 참조를
함께 고친다.**

## GUI 편집기

`Tools\MacroEditor\macro_editor.py`. Python 3 + tkinter로만 만들어져
추가 설치가 필요 없다. 프로젝트 루트의 **`매크로 편집기.bat`** 을 더블클릭해도 된다.

**화면 구성 (기본값)**

```text
[단계 추가 ▾] [복제] [사용/해제] | [▶ 실행 F5] [■ 중지]
┌───────────────┬──────────────────────┬──────────────┐
│ 매크로        │ 노드 그래프          │ 속성         │
│ 라이브러리    │  (또는 단계 트리)    │  선택한 노드 │
├───────────────┤                      │  의 입력 폼  │
│ 프로젝트      │                      │              │
│  폴더/리소스  │                      │              │
├───────────────┴──────────────────────┴──────────────┤
│ 실행 로그                                            │
└──────────────────────────────────────────────────────┘
```

전체 화면은 다크 테마다. 색 정의는 `Tools\MacroEditor\theme.py` 한 곳에 있다.

**패널 위치 바꾸기**

패널 제목줄을 끌어서 다른 영역에 놓으면 옮겨진다. 영역은 넷이다 —
`왼쪽` `가운데` `오른쪽` `아래`. 한 영역에 여러 패널이 오면 세로로 쌓인다.

* 제목줄 **드래그** → 끌고 다니는 동안 어느 영역에 놓일지 표시된다
* 제목줄 **우클릭** → 영역을 골라 보내기
* 메뉴 `보기` → 패널별 위치 지정, `레이아웃 초기화`, `레이아웃 지금 저장`

**레이아웃은 자동 저장된다.** 편집기를 닫을 때 `Tools\MacroEditor\layout.json` 에
패널 배치·분할선 위치·창 크기·프로젝트 트리에서 펼쳐 둔 폴더가 기록되고,
다음에 열면 그대로 복원된다. 이 파일을 지우면 기본 배치로 돌아간다.

**분할선 복원의 함정 (실제로 났던 버그):** 창이 화면에 그려지기 전에
`sashpos()` 를 부르면 값이 0 으로 잘려 패널이 전부 접힌다. 배치와 창 크기는
멀쩡히 복원되는데 화면만 무너져서 "레이아웃이 초기화됐다"로 보인다.
그래서 분할선은 패널들이 실제 크기를 가질 때까지 기다렸다가 적용하고,
반대로 아직 안 그려진 상태에서 읽은 0 값은 저장하지 않는다.

이 파일을 손으로 편집할 때는 **BOM 없이 UTF-8** 로 저장한다.
메모장이나 `Out-File -Encoding utf8` 은 BOM 을 붙인다 —
읽기는 BOM 을 허용하도록 해 두었지만 굳이 붙일 이유는 없다.

**구현 메모:** tkinter는 위젯의 부모를 바꿀 수 없어서, 배치가 바뀌면 패널 내용을
다시 짓는다. 그래서 로그 내용·캔버스 확대율·선택 상태는 따로 넘겨받아 복원한다.
(`docking.py` 의 `save_state` / `restore_state`)

**툴바에서 뺀 기능**

`삭제` `위로` `아래로` 버튼은 없앴다. 대신 이렇게 쓴다.

| 하려는 것 | 노드 그래프 | 단계 트리 |
|---|---|---|
| 삭제 | 노드 우클릭 → 삭제, 또는 선택 후 `Delete` | 우클릭 → 삭제, `Delete` |
| 순서 이동 | 노드를 드래그해서 옮긴다 | 우클릭 → 위로 / 아래로 |
| 복사 | 선택 후 `Ctrl+C` → `Ctrl+V` (다른 매크로에도 붙는다) | 우클릭 → 복제 |
| 복제 | 선택 후 `Ctrl+D` (여러 개면 연결까지 함께) | 우클릭 → 복제, `Ctrl+D` |

**프로젝트 패널 (Unity Editor의 Project 창에 해당)**

`Macros` 폴더의 구조와 리소스를 트리로 보여준다.

```text
📁 폴더   🧩 macro.json   🖼 이미지   📄 그 외
```

* 이미지를 고르면 아래에 **미리보기와 원본 크기·용량**이 나온다
* `macro.json` 더블클릭 → 그 매크로를 연다
* 이미지 더블클릭 → **지금 선택된 노드의 이미지로 지정**한다
* 이미지 우클릭 → 노드에 지정 / 이름 변경 / 삭제 / 탐색기에서 열기

이미지 이름을 바꾸면 **그 이미지를 참조하는 단계도 함께 고친다.**
삭제할 때는 참조하는 곳이 몇 군데인지 먼저 알려준다.

미리보기는 tkinter 기본 `PhotoImage`로 처리한다(PNG 지원). 외부 라이브러리가 없다.
축소는 정수 배율만 가능해서 썸네일 크기가 딱 떨어지지 않을 수 있다.

**기본 흐름**

1. 파일 > 새 매크로 → 이름 입력
2. 파일 > 저장 (이미지가 저장될 폴더가 정해진다. 캡처 전에 먼저 저장해야 한다)
3. [단계 추가]에서 단계를 고른다
4. 오른쪽 속성에서 값을 채운다
5. F5로 실행. 로그가 아래에 실시간으로 흐른다

**중첩 단계 만들기**

`조건 분기`나 `반복`을 추가하면 트리에 `[참일 때]` `[거짓일 때]` `[반복 본문]`
표시줄이 생긴다. 그 표시줄을 선택한 상태에서 [단계 추가]를 하면 그 안으로 들어간다.

**화면에서 집어오기**

| 버튼 | 하는 일 |
|---|---|
| 이미지 [캡처] | 화면을 드래그해 영역을 고르면 OculiX가 캡처해 매크로 폴더에 PNG로 저장 |
| 이미지 [선택] | **이미 있는 이미지를 썸네일로 보고 고른다** (아래 참조) |
| 좌표 [찍기] | 화면을 클릭해 좌표를 가져온다 |
| 색 [찍기] | 화면을 클릭해 그 지점의 RGB와 좌표를 함께 가져온다 |
| 영역 [드래그] | 검색 범위를 드래그로 지정 |

이미지 캡처는 OculiX를 호출하므로 JVM 기동에 몇 초 걸린다.
편집기가 직접 캡처하지 않는 이유는 좌표계 때문이다(아래).

**이미 있는 이미지 쓰기 — [선택] 버튼**

썸네일 목록에서 고른다. 세 갈래가 있다.

| 어디에 있는 이미지 | 결과 |
|---|---|
| 이 매크로 폴더 | 파일 이름만 저장 (`"image": "target.png"`) |
| 다른 매크로 폴더 | 이 매크로 폴더로 **복사**한 뒤 이름 저장 |
| 아무 위치 (`파일에서 가져오기...`) | 이 매크로 폴더로 **복사**한 뒤 이름 저장 |

**바깥 이미지를 절대 경로로 참조하지 않고 복사하는 이유**는 매크로 폴더만
옮겨도 그대로 돌아가야 하기 때문이다. 절대 경로로 두면 폴더를 옮기거나
다른 PC로 가져가는 순간 깨진다.

이름이 겹치면 덮어쓸지 다른 이름으로 저장할지 물어본다.

프로젝트 패널에서 이미지를 더블클릭해도 선택한 노드에 지정된다.
그때도 다른 폴더의 이미지면 복사할지 확인한다.

**도구 메뉴**

* `매크로 검사` — 엔진이 거부할 정의(while에 maxIterations 없음 등)와
  참조하는데 없는 이미지를 미리 찾아준다. 실행 전에 자동으로도 돌아간다
* `좌표계 대조` — 화면에서 한 점을 찍으면 편집기와 OculiX가 각각 그 좌표의
  색을 읽어 비교한다. 둘이 다르면 좌표계가 어긋난 것이다
* `화면 정보` — 논리/물리 해상도와 배율
* `실행이 끝나면 Windows 알림` (체크) — 매크로가 끝났을 때 알림 센터에 띄운다.
  긴 매크로는 사용자가 다른 창을 보는 동안 도니까 상태줄만으로는 놓친다.
  정상 종료 / 단계 실패로 중단 / 중지 / 종료 코드를 구분해서 알린다.
  기본값은 켬이고, 켜고 끈 상태는 `layout.json` 의 `notify_on_done` 에 남는다.
  외부 패키지 없이 PowerShell 로 WinRT 토스트를 부른다
  (`Tools\MacroEditor\notify.py`).

**화면에서 고를 때 편집기 창**

좌표·색·영역을 고르거나 화면을 캐프처할 때 편집기 창을 잠시 숨긴다.
이때 **창 크기·위치와 최대화 상태를 기억해 두었다가 그대로 되돌린다.**
tkinter 의 `withdraw()` → `deiconify()` 는 최대화를 풀고 크기를 초기값으로
되돌리기 때문이다 — 캐프처할 때마다 창이 튀던 문제였다.

**좌표계 주의 (이 PC에서 실측 확인)**

```text
창 / 커서 / 마우스로 찍은 좌표  ->  논리 좌표 (2048x1152) - OculiX와 일치
Windows GDI 화면 캡처            ->  물리 좌표 (2560x1440) - 1.25배
```

그래서 마우스로 찍은 좌표는 그대로 매크로에 넣어도 되지만,
화면 캡처는 OculiX에 맡긴다. 직접 캡처하면 배율이 어긋나 실행 시점에
매칭이 실패한다. 편집기가 이 처리를 대신 한다.

**검증 상태**

```text
selftest.py   데이터 모델 / 스키마 / 검증 규칙   49개 통과
guitest.py    GUI 코드 경로 (모든 단계·조건 폼)  54개 통과
끝단 확인     편집기 출력 -> OculiX 실행         exit 0
```

`guitest.py`는 마우스 클릭을 흉내내지 않고 위젯 생성 함수를 직접 호출한다.
속성 폼은 단계 종류마다 다른 위젯을 만들어서, 한 종류라도 깨지면 그 단계를
고르는 순간 편집기가 죽는다. 그 사고를 자동으로 잡기 위한 것이다.

**아직 사람이 직접 확인해야 하는 것**

마우스·키보드로 실제 조작하는 부분(클릭, 드래그, 피커 오버레이 동작)은
자동 검증이 불가능해서 손으로 써봐야 한다.

---

**왜 코드 생성이 아니라 JSON인가**
GUI 편집기가 매크로를 다시 열어 수정할 수 있어야 한다.
생성된 파이썬 코드를 되파싱하는 것은 깨지기 쉽다.
단계를 데이터로 두면 순서 변경·복제·비활성화가 전부 공짜로 되고,
OculiX API를 만지는 곳이 엔진 한 군데로 모인다.

## 폴더 구조 — 라이브러리에 뜨는 조건

**매크로 하나는 폴더 하나**가 기본이다. 이미지는 JSON 옆에 둔다.

```text
Macros\MyMacro\
├─ macro.json        ← 이 이름이어야 한다
├─ start.png
└─ confirm.png
```

JSON에서 `"image": "start.png"`로 쓰면 이 폴더에서 찾는다.
폴더째 옮겨도 그대로 동작한다.

편집기 라이브러리는 `Macros` 아래를 훑어 다음 두 가지를 인식한다.

| 놓인 모양 | 참조 이름 | 비고 |
|---|---|---|
| `Macros\이름\macro.json` | `이름` | 표준형 |
| `Macros\이름\아무거나.json` | `이름/아무거나.json` | 정상. 이미지도 그 폴더에서 찾는다 |
| `Macros\이름.json` | `이름.json` | 폴더 없이 루트에 놓임. 목록에 `⚠ Macros 루트` 표시 |

매크로가 아닌 `.json`(형식이 안 맞거나 깨진 파일)은 목록에서 제외된다.

**중요한 건 파일 이름이 아니라 폴더다.** 매크로 파일이 자기 폴더 안에 있으면
이름이 `macro.json` 이 아니어도 이미지 경로가 정상이다.

문제가 되는 건 `Macros` **루트에 그냥 놓인** 경우다. 그러면 이미지 기준 폴더가
Macros 루트가 되어 여러 매크로의 이미지가 한곳에 뒤섞인다.
이때만 목록에 `⚠ Macros 루트` 가 붙고, 우클릭 → `폴더로 정리 (권장)` 로
자기 폴더로 옮길 수 있다. 옮기면서 호출하는 곳의 참조도 함께 고친다.

`[다른 이름으로 저장]` 은 **이름만 물어보고 `Macros\<이름>\macro.json` 으로 저장한다.**
예전에는 파일 대화상자를 열어서, 이름만 바꿔 저장하면 폴더 없이 루트에 놓이기 쉬웠다.

## 시작 노드 주의

노드를 처음 추가하면 그 노드가 자동으로 시작 노드가 된다.
나중에 앞쪽에 노드를 더 붙이면 **시작 노드가 여전히 예전 노드에 머물러 있어**
매크로가 중간부터 실행된다.

검사(`도구 > 매크로 검사`)가 이 경우를 짚어준다.

```text
경고: 시작 노드 n2 가 다른 노드의 연결을 받고 있습니다.
      실제 시작은 n3 인 것 같습니다 — 노드를 우클릭해 '시작 노드로 지정'을 확인하세요.
```

시작 노드는 캔버스에서 초록 테두리와 `시작` 표시로 구분된다.

## 전체 구조

```json
{
  "name": "매크로 이름",
  "version": 1,
  "settings": {
    "screen": 0,
    "defaultSimilarity": 0.90,
    "defaultTimeout": 10,
    "searchRegion": [100, 100, 800, 600],
    "stepDelay": 0
  },
  "steps": [ ... ]
}
```

| settings | 뜻 | 기본값 |
|---|---|---|
| `screen` | 사용할 모니터 번호 | `0` |
| `defaultSimilarity` | 이미지 일치 임계값 | `0.90` |
| `defaultTimeout` | 대기 단계의 기본 제한시간(초) | `10` |
| `searchRegion` | 기본 검색 영역 `[x,y,w,h]`. 생략 시 전체 화면 | 전체 |
| `stepDelay` | 단계 사이 강제 대기(초) | `0` |

---

## 모든 단계에 공통인 필드

| 필드 | 뜻 |
|---|---|
| `type` | 단계 종류 (필수) |
| `label` | 로그에 표시할 이름. 없으면 `type`이 표시된다 |
| `enabled` | `false`면 건너뛴다. GUI에서 단계를 임시로 끌 때 쓴다 |
| `onFail` | `"continue"`면 실패해도 다음 단계로 진행. 기본은 매크로 중단 |

## 단계 종류

### 기본

```json
{ "type": "log", "message": "여기까지 완료" }
{ "type": "wait", "seconds": 1.5 }
```

### 프로그램 실행 (`run`)

앱이나 문서를 직접 실행한다. 시작 메뉴를 이미지로 클릭하는 것보다 훨씬 안정적이다.

```json
{ "type": "run", "label": "Hyper-V 관리자",
  "command": "virtmgmt.msc", "useShell": true }
```

| 필드 | 뜻 |
|---|---|
| `command` | 실행할 프로그램·문서·URL. `virtmgmt.msc`, `notepad.exe`, `D:/Tools/app.exe` |
| `args` | 인자. 공백으로 구분하고, 공백이 든 인자는 `"큰따옴표"` 로 묶는다 |
| `useShell` | 기본 `true`. Windows 연결 프로그램으로 연다 |
| `waitForExit` | 끝날 때까지 기다린다. `useShell: false` 일 때만 의미가 있다 |
| `timeout` | 기다릴 때의 제한(초). 기본 30 |
| `workingDir` | 작업 폴더 |

**`useShell` 을 언제 켜고 끄나**

| | 켬 (기본) | 끔 |
|---|---|---|
| 방식 | `cmd /c start` 로 연결 프로그램에 맡김 | 실행 파일을 직접 실행 |
| `.msc` `.lnk` 문서 URL | **열린다** | 열리지 않는다 |
| 종료 대기 / 종료 코드 | 불가 (시작만 하고 넘어감) | 가능 |

`.msc`(관리 콘솔), `.lnk`(바로가기), 문서, URL 은 실행 파일이 아니라
"연결 프로그램으로 여는 대상"이라 `useShell` 이 켜져 있어야 한다.
반대로 실행 결과(종료 코드)를 확인하려면 꺼야 한다.

**실패로 보는 경우**

* 명령이 비어 있음 (작성 시점 검사에서 잡힌다)
* 프로그램을 찾지 못함
* 작업 폴더가 없음
* `waitForExit` 인데 제한 시간 안에 끝나지 않음
* `waitForExit` 인데 종료 코드가 0이 아님

실패하면 `실패` 핀으로 흐른다.

**앱을 띄우는 권장 방식**

```text
[프로그램 실행] --다음--> [창이 뜰 때까지 대기] --다음--> [본 작업]
       |
       +--실패--> [로그: 실행 실패]
```

`run` 으로 띄우고, 창이 뜬 것은 `이미지 나타날 때까지 대기` 로 확인한 뒤
그 다음부터 이미지 기반 자동화를 한다. 시작 메뉴를 거치지 않으므로
아이콘 위치·스크롤·메뉴가 닫히는 타이밍 문제에서 자유롭다.

**주의**: 이 노드는 임의의 명령을 실행한다. 남이 만든 매크로를 실행하기 전에는
`run` 노드의 `command` 를 확인하는 편이 좋다.

### 이미지 대기

```json
{ "type": "waitImage",  "image": "start.png", "timeout": 10, "similarity": 0.9,
  "region": [100, 100, 400, 300] }

{ "type": "waitVanish", "image": "loading.png", "timeout": 30 }
```

`waitImage`는 찾으면 성공, 제한시간 안에 못 찾으면 실패다.
`region`을 주면 그 영역만 검색한다 — **빠르고 오탐이 적으므로 되도록 지정하라.**

### 글자 찾기 (OCR)

이미지 대신 **화면에 보이는 글자**로 찾을 수도 있다.
버튼 모양이 자주 바뀌거나 템플릿을 캡처하기 번거로울 때 쓴다.

```json
{ "type": "waitText", "text": "확인", "timeout": 10,
  "region": [248, 491, 220, 60] }
```

조건으로도 쓴다.

```json
{ "type": "textExists",  "text": "CLICK",   "region": [248, 491, 220, 60] }
{ "type": "textMissing", "text": "Loading", "region": [248, 491, 220, 60] }
```

클릭 계열 노드에도 `text` 를 줄 수 있다. 찾은 글자의 중앙을 누른다.

```json
{ "type": "click", "text": "CLICK", "region": [248, 491, 220, 60] }
```

우선순위는 **`image` → `text` → `point`** 다. 이미지가 있으면 텍스트는 무시된다.

#### 일치 규칙

**대소문자와 공백을 무시한 부분 일치**다. 화면의 한 단어 또는 한 줄 안에
찾는 글자가 들어 있으면 성공이다.

| 화면에 있는 글자 | 찾는 글자 | 결과 |
|---|---|---|
| `CLICK ME` | `CLICK` | 찾음 |
| `CLICK ME` | `click me` | 찾음 (대소문자 무시) |
| `OCULIX-TARGET` | `OCULIX-TARGET` | 찾음 |
| `OCULIX- TARGET` | `OCULIX-TARGET` | 찾음 (공백 무시) |
| `CLICK ME` | `CLICK-ME` | 못 찾음 |

한글은 **음절마다 따로** 읽힌다. `설정 열기` 는 `설`, `정`, `열`, `기` 네 조각이
되고, 어느 조각에도 `설정` 이 통째로 들어 있지 않다. 그래서 엔진은 조각을
하나씩 보지 않고 **전부 이어붙인 뒤** 위치를 찾고, 질의가 걸친 조각들만 합쳐
사각형을 만든다. 덕분에 `설 정 열 기` 줄 전체가 아니라 `설정` 두 글자를
가리키고, 영문에서도 `ME` 로 찾으면 `CLICK ME` 줄이 아니라 `ME` 를 가리킨다.

| 화면에 있는 글자 | 찾는 글자 | 결과 |
|---|---|---|
| `설정 열기` (읽힌 값 `설 정 열 기`) | `설정` | 찾음 |
| `설정 열기` | `설정 열기` | 찾음 |
| `다음 단계로 진행` | `단계로` | 찾음 |
| `Hyper-V 관리자` | `관리자` | 찾음 |
| `Hyper-V 관리자` | `Hyper-V 관리자` | 못 찾음 (아래 "인식 언어" 참조) |

단어 목록과 줄 목록을 **둘 다** 시도한다. 같은 화면인데도 실행마다 한쪽이
글자를 놓치기 때문이다 — 한 번은 단어 목록이 `확인` 을 놓치고 줄 목록이 잡았고,
다음 실행에서는 반대였다. 위치가 필요 없는 판정(`textExists` / `textMissing`)은
마지막으로 영역 전체를 통짜로 읽어보는 단계가 하나 더 있다.

> 엔진은 OculiX 의 `existsText()` 를 쓰지 않는다. 그 함수의 일치 규칙이 단순
> 부분 일치가 아니기 때문이다. 실측하면 화면에 `OCULIX-TARGET` 이 있을 때
> `existsText` 는 `OCULIX` 와 `OCULIX-` 는 찾지만 `OCULIX-TARGET` 과 `-TARGET`
> 은 찾지 못한다. 붙임표 뒤가 잘린다. 매크로를 쓰는 사람이 예측할 수 없는
> 규칙이라 엔진이 읽은 글자를 직접 훑는다.

#### 영역을 반드시 좁혀라

이미지 검색보다 훨씬 중요하다. 같은 라벨을 읽어도 이렇게 갈린다.

```text
라벨 영역만 (430x55)   ->  "OCULIX-TARGET"          정확
창 전체    (800x560)  ->  "OCULIX- TARGET" 외 2줄   공백 삽입, 대부분 누락
```

글자가 작거나 배경과 대비가 낮으면 더 나빠진다. 잘 안 잡히면 먼저 영역을
좁히고, 그다음 찾는 글자를 짧은 한 단어로 줄여 본다.

속도 차이도 크고, 넓으면 **엉뚱한 창의 같은 글자를 짚는다.**

```text
좁은 라벨 영역          0.07 ~ 0.09s
창 하나 (560x340)      0.15 ~ 0.16s
주 모니터 전체          2.2s   ← 게다가 의도한 라벨이 아닌 다른 글자를 짚었다
```

편집기는 영역 없이 글자를 찾는 노드에 경고를 띄운다. 오류는 아니지만
그대로 두면 매크로가 조용히 엉뚱한 곳을 누른다.

#### 인식 언어

현재 이 PC에 설치된 언어다. `kor` 은 2026-08-21 에 추가로 설치했다
(출처와 SHA-256 은 `Docs\Environment.md` 에 기록).

```text
chi_sim, eng, fra, hin, kor, spa      (기본값 eng)
```

**한 번에 한 언어만 된다.** OculiX 는 Tesseract 의 `kor+eng` 같은 조합 표기를
거부한다. 그래서 언어가 어긋나면 결과가 조용히 망가진다.

```text
kor 로 영문 읽기 : "Open Settings"  ->  "0060 56 네 ㅁ 095"
eng 로 한글 읽기 : "설정 열기"       ->  "a4 F7|"
kor 로 혼용 읽기 : "Hyper-V 관리자"  ->  "1/00-\/ 관 리 자"   (한글만 맞음)
```

→ 한글·영문이 섞인 라벨은 **한쪽만** 질의에 넣는다. `Hyper-V 관리자` 는
`관리자` 로 찾는다.

매크로 전체 기본값은 설정에, 화면마다 다르면 노드마다 지정한다.

```json
"settings": { "ocrLanguage": "kor" }
```

```json
{ "type": "click", "text": "확인", "ocrLanguage": "kor",
  "region": [1268, 361, 64, 42] }
```

노드에 지정하지 않으면 매크로 설정값을 쓰고, 그것도 없으면 `eng` 다.
없는 언어를 지정하면 매크로를 멈추지 않고 경고를 남긴 뒤 이전 언어로 계속한다.

#### 인식이 비어 나올 때 (ocrPsm)

Tesseract 의 페이지 분할 모드다. 기본값은 **11**(성긴 글자)로 정해 두었다.
Tesseract 자체 기본값인 3(자동)은 UI 화면에 맞지 않아서, 라벨에 여백을 조금만
둬도 인식 결과가 통째로 비는 일이 있었다.

```text
한글 창 9가지 조합    psm=3  5/9 (1.58s)   psm=4  9/9 (1.02s)   psm=11  9/9 (0.99s)
영문 창 8가지 조합    psm=3  7/8 (0.66s)   psm=4  7/8 (0.50s)   psm=11  7/8 (0.51s)
```

로그에 `Empty page!!` 가 보이면 이 값이나 영역 크기를 의심한다.

```json
"settings": { "ocrPsm": 11 }
```

쓸 만한 값: `11` 성긴 글자, `4` 세로로 늘어선 글줄, `7` 한 줄, `3` 자동.

### 클릭

```json
{ "type": "click",       "image": "ok.png" }
{ "type": "click",       "point": [500, 300] }
{ "type": "doubleClick", "image": "icon.png" }
{ "type": "rightClick",  "image": "item.png" }
{ "type": "hover",       "image": "menu.png" }
```

`image`를 주면 찾아서 클릭하고, `text` 를 주면 그 글자를 찾아 클릭하고,
`point`를 주면 절대 좌표를 클릭한다. 우선순위는 `image` → `text` → `point` 다.

**이미지로 찾은 경우 찾은 영역의 정중앙을 누른다.**
실행 로그에 어디를 눌렀는지 남으므로 눈으로 확인할 수 있다.

```text
--> 버튼 클릭
    button.png 발견 score=0.9962  영역 (248,491) 220x60  ->  클릭 지점 (358,521)
```

중앙이 아닌 곳을 누르게 하려면 `targetOffset` 을 준다.
그때는 로그에 `(targetOffset [x, y] 적용)` 이 함께 나온다.
레이블은 뚜렷한데 눌러야 할 버튼은 그 아래에 있을 때 쓴다.

```json
{ "type": "click", "image": "label.png", "targetOffset": [0, 30] }
```

### 마우스 버튼 / 드래그 / 휠

```json
{ "type": "mouseDown", "button": "LEFT" }
{ "type": "mouseUp",   "button": "LEFT" }

{ "type": "drag", "from": { "image": "item.png" }, "to": { "point": [800, 400] } }

{ "type": "wheel", "point": [600, 400], "direction": "down", "amount": 3 }
```

`button`은 `LEFT` / `MIDDLE` / `RIGHT`.

### 키보드

```json
{ "type": "type", "text": "hello" }
{ "type": "type", "text": "안녕하세요", "usePaste": true }
{ "type": "key",  "key": "ENTER" }
{ "type": "key",  "key": "a", "modifiers": ["CTRL"] }
```

**한글이나 긴 문자열은 `"usePaste": true`를 쓰라.** 클립보드를 경유해서
`type()`보다 안정적이다.

### 특수키는 손으로 타이핑하지 않는다

`key` 노드를 고르면 속성에 조합이 이렇게 표시되고, `[선택...]` 버튼이 붙는다.

```text
키    Ctrl + Shift + Enter     [선택...]
```

선택 창은 두 가지 방법을 함께 준다.

1. **키 캡처** — 창을 열면 바로 캡처 상태가 된다. 원하는 키를 그냥 누르면
   조합키까지 한 번에 잡힌다. 오타가 불가능하다.
2. **목록** — Windows가 가로채는 키(Win 단독, PrintScreen, Alt+Tab 등)는
   캡처되지 않으므로 그룹별 목록에서 고른다.

캡처는 수정키의 누름/뗌을 직접 추적한다. `event.state` 비트마스크는 플랫폼마다
값이 달라 신뢰할 수 없기 때문이다.

**사용 가능한 키 60개** (OculiX 4.0.0에서 직접 조회한 목록):

```text
자주 쓰는 키  ENTER TAB SPACE BACKSPACE DELETE INSERT ESC
이동          UP DOWN LEFT RIGHT HOME END PAGE_UP PAGE_DOWN NEXT
기능키        F1 ~ F15
숫자패드      NUM0~NUM9 ADD MINUS MULTIPLY DIVIDE DECIMAL SEPARATOR NUM_LOCK
수정키 단독   SHIFT CTRL ALT ALTGR WIN CMD META
시스템        PRINTSCREEN SCROLL_LOCK PAUSE CAPS_LOCK CONTEXT
```

`modifiers`는 `CTRL` `SHIFT` `ALT` `ALTGR` `META`.
**`WIN` / `CMD` / `META` 는 OculiX에서 값이 모두 4로 같다** — 선택 창에는
`Win` 하나만 노출한다.

키 이름이 아닌 한 글자(`"a"`, `"1"`)를 넣으면 그 문자가 그대로 입력된다.
다만 `MINUS` 처럼 키 상수와 같은 이름은 숫자패드 키로 해석되니 주의한다.

### 픽셀 색 대기

```json
{ "type": "waitColor", "point": [500, 300], "rgb": [30, 160, 60],
  "tolerance": 12, "timeout": 5, "interval": 0.1 }
```

`tolerance`는 RGB 채널별 허용 오차다. `[10, 5, 20]`처럼 채널마다 다르게도 된다.

## 조건 분기

```json
{
  "type": "if",
  "condition": { "type": "imageExists", "image": "popup.png", "timeout": 3 },
  "then": [ { "type": "click", "image": "close.png" } ],
  "else": [ { "type": "log", "message": "팝업 없음" } ]
}
```

`else`는 생략 가능하다.

### 조건 종류

```json
{ "type": "imageExists",  "image": "x.png", "timeout": 3, "similarity": 0.9,
  "region": [0, 0, 500, 500] }

{ "type": "imageMissing", "image": "x.png", "timeout": 3 }

{ "type": "textExists",   "text": "확인",    "timeout": 3,
  "region": [0, 0, 500, 500] }

{ "type": "textMissing",  "text": "Loading", "timeout": 3 }

{ "type": "colorMatches", "point": [100, 200], "rgb": [200, 30, 30], "tolerance": 10 }

{ "type": "not", "condition": { ... } }

{ "type": "all", "conditions": [ { ... }, { ... } ] }
{ "type": "any", "conditions": [ { ... }, { ... } ] }
```

조건에서 쓰는 `timeout`은 기본 3초다. 조건 판정에 10초씩 쓰면 매크로가 느려지므로
분기용은 짧게 두는 편이 낫다.

## 반복

### 횟수 지정

```json
{
  "type": "repeat",
  "times": 5,
  "steps": [
    { "type": "click", "image": "next.png" },
    { "type": "wait", "seconds": 0.5 }
  ]
}
```

### 조건이 참인 동안

```json
{
  "type": "repeat",
  "while": { "type": "imageExists", "image": "more.png", "timeout": 2 },
  "maxIterations": 20,
  "steps": [ { "type": "click", "image": "more.png" } ]
}
```

**`while`에는 `maxIterations`가 필수다.** 없으면 엔진이 정의 오류로 거부한다.
무한 루프를 만들 수 없게 형식 차원에서 막아 둔 것이다.
상한은 10000이고, 그 이상은 거부된다.

**반복 방식(`times` / `while` / `forEach`)은 하나만 고를 수 있다.**
둘 이상 적으면 뜻이 둘이 되기 때문에 검사와 엔진이 모두 거부한다. 예전에는 `times`가 조용히 이겨서, 조건을 넣어 둔 반복이 조건을
한 번도 평가하지 않았다 (`"times": 0`이면 본문 없이 곧장 `완료` 핀으로 나갔다).
편집기에서는 조건을 고르면 횟수가, 횟수를 넣으면 조건이 자동으로 빠진다.

조건은 **참인 동안 도는 것**이지 종료 조건이 아니다. "이미지가 보일 때까지"
기다리려면 `imageMissing`("이미지가 없으면")을 쓴다 — 화면에 없는 동안 돌고,
나타나면 `완료`로 나간다.

`maxIterations`에 도달해도 기본적으로는 실패로 치지 않는다.
도달을 실패로 다루려면 `"allowMaxIterations": false`를 준다.

### 값 목록으로 반복 (`forEach`)

값을 하나씩 변수에 넣으며 돈다. 매 회 다른 값으로 같은 일을 시킬 때 쓴다 —
같은 호출을 값만 바꿔 복사해 두던 것을 하나로 줄인다.

```json
{
  "type": "repeat",
  "forEach": { "param": "charNo", "type": "int", "values": [2, 3, 4, 5, 6] }
}
```

* `param` — 변수 이름. **선언된 매개변수(`params`)와 같은 이름은 쓸 수 없다.**
  같으면 반복이 도는 동안 매개변수가 가려져서 어느 쪽 값인지 알 수 없어진다
* `type` — `int` / `float` / `string` / `bool`. 값을 이 타입으로 맞춘 뒤 넣는다.
  문자열 `"3"`과 숫자 `3`이 섞이면 비교 조건이 말없이 어긋나기 때문이다
* `values` — 하나 이상. 개수가 곧 반복 횟수다 (상한 10000)

**변수는 본문 안에서만 산다.** 반복이 끝나면 이전 값으로 되돌아가므로,
루프 밖에서 남은 값을 실수로 읽는 일이 없다. 같은 이름으로 중첩해도
안쪽이 끝나면 바깥 값이 그대로 돌아온다.

#### 변수를 호출에 넘기기

`call` 노드의 `args`에서 `{"$param": "이름"}`으로 참조한다.
편집기에서는 값 칸에 `$이름`이라고 적으면 된다.

```json
{
  "type": "call",
  "macro": "./MBM_CharSelect",
  "args": { "param1": { "$param": "charNo" } }
}
```

조건에서도 그냥 읽을 수 있다.

```json
{ "type": "paramCompare", "param": "charNo", "op": "==", "value": 3 }
```

**반복 본문 밖에서 참조하면 실행이 멈춘다.** 비워서 넘기면 왜 안 먹는지
찾을 수 없기 때문에, 범위에 없는 이름은 조용히 넘어가지 않고 오류로 알린다.

전체 예 — 캐릭터 2~6번에게 같은 일을 시킨다.

```json
{
  "nodes": [
    { "id": "L", "type": "repeat",
      "forEach": { "param": "charNo", "type": "int", "values": [2,3,4,5,6] } },
    { "id": "sel", "type": "call", "macro": "./MBM_CharSelect",
      "args": { "param1": { "$param": "charNo" } } },
    { "id": "work", "type": "call", "macro": "./Daily_Char_Routine" }
  ],
  "links": [
    { "from": "L",   "pin": "body", "to": "sel" },
    { "from": "sel", "pin": "next", "to": "work" }
  ]
}
```

`work`에 이어지는 링크가 없으므로 본문이 끝나고 다음 값으로 넘어간다.

### 루프 탈출

```json
{ "type": "break" }
```

가장 안쪽 `repeat`를 빠져나온다. 보통 `if` 안에서 쓴다.

## 예제

`Macros\Example\macro.json`이 제어 흐름 전체를 시연하는 검증용 매크로다.
입력 주입 없이 돌아가므로 지금 상태에서도 실행된다.

실제 매크로 패턴은 이런 모양이 된다.

```json
{
  "name": "일일 보상 수령",
  "settings": { "searchRegion": [1200, 400, 700, 600], "defaultTimeout": 15 },
  "steps": [
    { "type": "click", "label": "메뉴 열기", "image": "menu.png" },
    { "type": "waitImage", "label": "목록 로딩 대기", "image": "list_header.png", "timeout": 20 },
    {
      "type": "repeat", "label": "보상 전부 수령",
      "while": { "type": "imageExists", "image": "claim_button.png", "timeout": 2 },
      "maxIterations": 30,
      "steps": [
        { "type": "click", "image": "claim_button.png" },
        { "type": "wait", "seconds": 0.4 },
        {
          "type": "if",
          "condition": { "type": "imageExists", "image": "confirm.png", "timeout": 2 },
          "then": [ { "type": "click", "image": "confirm.png" } ]
        }
      ]
    },
    { "type": "click", "label": "닫기", "image": "close.png" }
  ]
}
```

## 엔진이 강제하는 안전 규칙

1. 모든 이미지·색 대기에 제한시간이 있다. 생략하면 `defaultTimeout`이 적용된다
2. `while` 루프는 `maxIterations` 없이 정의할 수 없다
3. 반복 방식(`times` / `while` / `forEach`)은 하나만 고를 수 있다
4. 반복 횟수 상한은 10000이다
5. `forEach` 변수를 반복 본문 밖에서 참조하면 실행이 중단된다
6. 단계가 실패하면 기본적으로 매크로를 중단한다.
   계속하려면 그 단계에 명시적으로 `"onFail": "continue"`를 적어야 한다

6번이 중요하다. 실패를 무시하고 진행하면 엉뚱한 위치를 클릭하게 되는데,
이것이 매크로가 일으키는 사고의 대부분이다.
